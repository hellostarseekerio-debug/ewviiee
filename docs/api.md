# API Reference

Full interactive documentation is auto-generated by FastAPI at
`http://localhost:8000/docs` (Swagger UI) and `/redoc` when the API is
running. This page summarizes the endpoints.

Base URL: `http://localhost:8000`

## Authentication

### `POST /api/auth/users`

Create a user (typically restricted to setup/admin use).

```json
{ "username": "reviewer1", "password": "...", "full_name": "Jane Doe", "role": "reviewer" }
```

### `POST /api/auth/token`

OAuth2 password grant. Form-encoded `username` + `password`. Returns:

```json
{ "access_token": "...", "token_type": "bearer" }
```

Pass the token as `Authorization: Bearer <token>` on every other request.

## Documents

### `GET /api/documents`

Query params: `skip`, `limit`. Returns a list of `DocumentOut`.

### `GET /api/documents/{document_id}`

Returns a single document's full metadata, or 404.

## Search

### `GET /api/search`

Query params (all optional): `estate`, `district`, `workflow_name`,
`document_type`, `date_from`, `date_to`, `keyword`, `ocr_text`,
`politician`, `reference_number`, `filename`, `limit`, `offset`.

Returns `{ "total": int, "results": [DocumentOut, ...] }`.

## Workflows

### `GET /api/workflows`

Lists every workflow defined under `config/workflows/`, with its plugin id
and stage order.

### `POST /api/workflows/run`

```json
{
  "workflow_name": "housing_estate_poster",
  "document_paths": ["/abs/path/to/poster.png", "/abs/path/to/application.pdf"],
  "triggered_by": "jane.doe"
}
```

Runs each document through the named workflow synchronously and persists a
`Document` + `ProcessingEvent` row per document. Returns per-document
success/failure, halt reason (if any), output path, and extracted fields.

## Plugins

### `GET /api/plugins`

Lists currently enabled, successfully loaded plugins with id, display name
and version.

## Error format

FastAPI's standard `{"detail": "..."}` shape is used for all 4xx/5xx
responses. Workflow-level failures are not HTTP errors — they come back as
`success: false` entries in `/api/workflows/run`'s response with a
human-readable `halt_reason`, since a single bad document should not fail
the whole batch request.
